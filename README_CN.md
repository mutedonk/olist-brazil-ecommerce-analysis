# 巴西电商数据分析项目 | Python + SQL + PowerBI
## 项目概述
本项目基于 Kaggle 公开的 **Olist 巴西电商数据集**，完成完整的电商业务数据分析与可视化实战。

区别于传统盲目性探索分析，我先通过 **Python、SQL 双语言对照实现**，完成十余个业务问题的数据探索，充分熟悉数据特征。在挖掘出平台核心业务痛点——**巴西电商用户复购率极低、几乎无二次消费** 后，针对性开展三项核心建模分析：
- 同期群（Cohort）用户留存分析
- RFM 用户分层建模分析
- 产品与地域维度业务洞察分析

由于原始数据集质量极高、无明显脏数据，本项目采用 **SQL 仅筛选已交付有效订单** 的口径开展分析，剔除取消、退款无效订单干扰，保证分析结果贴合真实业务。最终通过 Power BI 完成核心结论可视化落地。

## 技术栈
- 数据处理与分析：Python（Pandas、Matplotlib、Seaborn）、SQL
- 数据库：SQLite
- 可视化工具：Matplotlib、Seaborn、Power BI
- 开发工具：VS Code、Jupyter Notebook

## 项目亮点
1. **双技术栈落地能力**：针对同一批业务分析问题，分别使用 Python、SQL 两套方案实现，熟练掌握数据查询、筛选、聚合、建模的全流程思路。
2. **业务驱动建模思维**：不盲目做数据分析，先探索数据发现「用户极低复购」核心痛点，再针对性开展留存分析、用户分层建模，分析逻辑贴合真实业务场景。
3. **标准化工程化结构**：严格区分正式分析代码、探索草稿代码、SQL脚本、可视化输出文件，符合企业数据分析项目规范。
4. **精准分析口径**：通过 SQL 筛选 `delivered` 已交付有效订单，剔除无效订单干扰，提升分析结果真实性与参考价值。

## 环境配置与运行教程
1. 安装项目依赖库
```bash
pip install -r requirements.txt
```
2. 数据准备
- 从 Kaggle 下载完整数据集，将所有 CSV 文件放入 `data` 文件夹
- 运行项目根目录 `import.py`，自动生成本地 `ecommerce.db` 数据库文件
- 注：超大数据库文件不上传至GitHub仓库

3. 项目运行
- 通过 `notebooks` 文件夹查看完整 EDA 探索与建模分析全过程
- 通过 `sql` 文件夹脚本，对照验证 Python 与 SQL 双向分析逻辑一致性

## 核心分析结论
1. **用户复购特征**：巴西电商平台用户复购率极低，绝大多数用户为一次性消费，无长期忠实用户，是平台核心业务短板。
2. **用户留存表现**：同期群分析证明，用户短期留存率断崖式下跌，用户复购消费习惯极差，用户粘性不足。
3. **用户价值分层**：RFM 建模发现用户价值两极分化严重，少量高价值客户贡献平台核心营收，绝大多数用户消费价值极低。
4. **地域与产品洞察**：巴西电商消费地域集中特征明显，东南部为核心消费区域；不同品类商品的订单量、客单价表现差异显著。
